## Ce qui est conservé

Pour convertir un export Confluence en Markdown, chaque fichier `.html` du .zip produit par l’export HTML d’un espace est lu. Par défaut, l’espace devient **un dossier de pages** : un document Markdown par page, un sous-dossier par section, et la page de la section elle-même en tête de ce sous-dossier. L’option **Un seul document** réunit plutôt toutes les pages dans un seul fichier.

| Dans l’export | Dans le Markdown |
| --- | --- |
| Le titre, écrit `Espace : Page` | `# Page`, sans le nom de l’espace |
| Le fil d’Ariane | Le dossier dans lequel la page est rangée |
| Titres, listes, gras, italique | La même chose, en Markdown |
| Un tableau | Un tableau Markdown, sa première ligne en en-tête |
| La macro Table des matières, un lien vers un titre | Un lien vers le slug du titre, à la manière de GitHub |
| Un lien vers une autre page | Un lien vers cette page, dans un dossier de pages |
| Une image sous `attachments/` | Intégrée à la page, les plus lourdes d’abord ramenées à 1 600 pixels au plus sur le grand côté |
| Un lien vers une adresse web | Conservé comme lien |

## Ce qui se perd

- **Les macros en tant que macros.** Aucune n’a de règle propre : chacune arrive sous la forme du HTML que l’export en a tiré, si bien qu’un panneau d’information devient ses paragraphes, sans le panneau.
- **Les cellules fusionnées.** Le texte se retrouve dans la première cellule couverte, et sous une cellule fusionnée vers le bas, la ligne se décale vers la gauche. Une cellule contenant plusieurs paragraphes ou une liste est ramenée sur une seule ligne.
- **Les pièces jointes qui ne sont pas des images.** Un PDF n’est pas emporté ; dans un dossier de pages, son lien devient donc son nom, comme les liens vers les écrans propres à Confluence.
- **Les images au-delà du budget.** Dans un dossier de pages, chaque page peut porter près de 4 Mo d’images, aucune au-delà de 1 Mo une fois encodée ; une image qui ne rentre plus devient son texte alternatif ou son nom de fichier en italique. Un seul document se partage 2 Mo, et une image au-delà garde son chemin `attachments/`.

## Un exemple

Un export d’espace dans lequel la page « Deploy checklist », rangée sous « Runbooks », contient une macro Table des matières, un titre, un tableau, un lien vers la page « Rollback », un `runbook.pdf` en lien et une capture d’écran. En dossier de pages, téléchargée en .zip, elle devient `Engineering/Runbooks/Deploy checklist.md` (données de l’image raccourcies, cadre de la page omis) :

```markdown
# Deploy checklist

- [Before you deploy](#before-you-deploy)

## Before you deploy

| Step | Owner |
| --- | --- |
| Tag the release | Ops |
| Announce the freeze | Release lead |

If it fails, follow [Rollback](Rollback.md). The full runbook is runbook.pdf.

![Pipeline](data:image/png;base64,iVBORw0KGgo…)
```

L’entrée de la table des matières pointait vers l’identifiant maison de Confluence, `Deploychecklist-Beforeyoudeploy`, et mène désormais au titre par son slug. En un seul document, la page serait une section sous une liste `# Contents` des titres de pages.

## Limites

Le .zip peut peser jusqu’à 250 Mo ; seules les pages et les images sont décompressées, et un .zip sans fichier `.html` est refusé. La conversion se fait dans votre navigateur : sans connexion, rien n’est téléversé ; connecté, rien n’arrive dans votre compte avant que vous n’enregistriez. Une page enregistrée peut peser jusqu’à 4 Mo.

Les pages sont classées par nom de fichier, `index.html` en premier, et non selon l’arborescence des pages de Confluence. Rien ne cherche à isoler le contenu principal : hormis le fil d’Ariane, le cadre de la page arrive sous forme de texte, par exemple un titre qui répète le nom de l’espace, une ligne d’auteur ou une ligne « Document generated by Confluence ». Vérifiez les blocs de code : un bloc de code délimité n’apparaît que là où le HTML contient `<code>` dans `<pre>`, et un `<pre>` seul arrive en simples lignes. Les coches ne sont lues que dans des cases à cocher HTML, sans règle pour les listes de tâches de Confluence.

Plus de détails sur les macros dans [convertir une page Confluence en Markdown](/blog/convert-confluence-page-to-markdown), et sur le .zip dans [ouvrir un .zip d’export](/how-to/open-zip).

## Questions

### S’agit-il d’une application ou d’un plugin Confluence ?

Non. Rien n’est installé dans Confluence et rien ne s’y connecte : vous exportez l’espace en HTML, puis vous déposez le .zip ici. [Les options gratuites comparées](/blog/free-confluence-to-markdown-converter) passent aussi en revue les applications du Marketplace.

### Cela fonctionne-t-il avec les exports de Confluence Cloud et de Data Center ?

Aucun des deux n’a de traitement à part : le convertisseur lit la même chose dans tout export HTML, à savoir le `<title>` de chaque page, son fil d’Ariane, les identifiants de ses titres et son nom de fichier. Dans tous les cas, cette page accepte le .zip de l’export HTML et aucun autre fichier.

### Peut-on convertir une seule page Confluence en Markdown ?

Oui, à condition qu’elle arrive en HTML dans un .zip. Chaque fichier `.html` de l’archive est lu, si bien qu’une page se convertit exactement comme six cents.

### Peut-on obtenir du HTML plutôt que du Markdown ?

Choisissez **Un seul document** : le menu de téléchargement du résultat propose le HTML, Word et le texte brut à côté du Markdown. Un dossier de pages se télécharge uniquement en Markdown.

### Les liens entre les pages fonctionnent-ils toujours ?

Dans un dossier de pages, oui : chacun pointe vers le document enregistré dans votre compte, ou vers le fichier de la page liée dans le .zip téléchargé. Dans un seul document, ils gardent les noms de fichier de l’export, qui ne mènent nulle part en dehors de lui.
